# subsidy 清洗模块架构

本文描述当前项目的清洗模块边界；整体调度、报表共享与运行验证见[项目架构](architecture.md)，字段和匹配规则见[清洗业务规则](cleaning-rules.md)。清洗模块属于`subsidy`库，无独立`clean`入口。

## 模块与边界

| 模块 | 职责 | 边界 |
|---|---|---|
| `app/cli.rs` | 读取并校验源目录路径 | 不含清洗或报表业务规则 |
| `app/runner.rs` | 取得运行锁，依次清洗并发布8类明细，再调用报表调度 | 单类别错误与 panic 隔离；记录本次成功发布类别 |
| `jobs/` | 文件识别、表头校验、字段转换、匹配、排序与标记 | `Job::run(&Path)`返回`Result<Table, ProcessError>`，不发布文件 |
| `model/` | 错误、值类型、列、行、结果表与填色 | 不依赖任务和文件 I/O |
| `io/paths.rs` | 输入路径、文件识别、输出目录与真实路径保护 | `国补明细/`和`国补报表/`均位于源目录父目录 |
| `io/xlsx_reader.rs` | 读取工作表，保留原始单元格类型 | 使用`Range::start()`换算 Excel 绝对坐标；工作表读取失败即报错 |
| `io/xlsx_writer.rs` | 按`Table`写单工作表 XLSX 临时文件 | 根据列类型设置格式，行业务填色优先于斑马纹 |
| `io/publisher.rs` | 临时文件、备份、正式替换与失败恢复 | 仅发布当前文件，恢复失败保留备份并报告残留路径 |
| `utils/` | 日期、十进制金额、文本、单据号处理 | 不访问文件系统 |

## 任务与数据模型

`jobs::registry()`按发票、数码上传、家电电脑上传、银联、家电电脑回款、数码回款、收款单、销售用券顺序执行。`uploaded.rs`和`refund.rs`各自复用同一实现处理两种品类。

`Table`包含列定义和明细行。`Value`区分空值、文本、十进制金额、整数、比例、日期与日期时间；`ColumnType`控制 Excel 类型和格式。金额使用`rust_decimal`；保留原精度与两位小数由`DecimalScale`区分。写出前执行`Table::validate()`检查列数一致性。

文本标识保留完整值与前导零；源日期不可解析时，按对应业务章节保留原值或报告错误，不统一猜测。黄色`#FFEB9C`与粉色`#FFC7CE`由行的`Fill`记录。

## 任务间只读复用

一次清洗阶段通过 `jobs/context.rs` 中的 `PipelineContext` 显式传递和管理成功解析的中间表和查询索引，彻底消除 thread-local 隐式通道。查询索引使用标准库 `Rc` 共享，下游有依赖的结果表直接存储；作用域结束释放，下次运行重新读取。不缓存原始工作簿或失败结果。

- 已上传任务引用对应回款任务的校验与结果，按订单号、参考号生成补贴金额和状态；未匹配审核终止记录金额留空且稳定沉底。回款不再读取已上传源补参考号。
- 银联任务提供权威参考号集合，发票任务提供单据号索引，收款单任务提供非空备注索引，供销售用券复用。
- 已上传状态索引由 `uploaded.rs` 按类别分别建立；销售用券按归并后财务大类选择该组参考号及发票号索引。回款补贴索引由 `refund.rs` 建立；列位置由各自输出布局的所有者维护。销售用券和已上传任务只消费索引。
- 索引构建通过 `PipelineContext::with_table()` 借用已清洗表；无缓存时在上下文中驱动原任务读取，匹配优先级与歧义处理一致。
- 被引用任务仅提供数据，不代替调度器发布结果。

收款单仅从实际退货出发，沿补差／换货链追溯正常销售原单；完整规则见[第9.5节](cleaning-rules.md#95-备注生成与关联匹配)。

## 发布与后续报表

```text
输入目录校验 → 创建国补明细目录并取得运行锁
  → Job::run → Table::validate → XLSX 临时文件 → 独立发布
  → 记录每类本次发布状态，失败继续后续类别
  → app/reports.rs 检查依赖 → 生成并发布报表 → 汇总退出状态
```

临时文件使用进程、时间与序号构造唯一名称。已有结果替换前备份；写入、替换或备份清理失败时恢复或保留旧结果。恢复和清理再次失败时报告原始错误、后续错误与残留路径。清理守卫覆盖提前返回和 panic。

报表只读取本次成功发布的标准明细，不通过旧文件绕过依赖检查。清洗与报表之间保持 Excel 文件边界，两类读取器各自处理对应数据契约。

## 验证入口

`src/`内测试覆盖业务转换、匹配、歧义、缓存、路径与故障恢复；`tests/cli.rs`经真实终端入口验证失败隔离，`tests/full_pipeline.rs`使用小型原始数据夹具验证8类清洗和两份报表的完整成功流程，`tests/publishing.rs`验证文件发布。`tests/acceptance_test.rs`经完整 CLI 验证2026-10-01原始数据副本，包括退货链、报表内容及源文件未变；默认忽略，需提供`COMBINE_SOURCE_DIR`。

构建、检查与样本验收命令见[运行与验证](architecture.md#运行与验证)。
