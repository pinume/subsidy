# subsidy 国补报表业务规则

## 1. 项目目标与安全约束

本文定义报表阶段：读取本次清洗成功发布的标准明细生成两份工作簿，并直接读取原始补贴明细生成两份台账，共4份报表。原始数据清洗见[清洗业务规则](cleaning-rules.md)，统一入口见 [README](../README.md)。章节编号供代码与测试引用，保留编号空缺。

报表输出：

1. **工作簿一**：`国补上传情况汇总.xlsx`（包含 5 个标准 Sheet）
2. **工作簿二**：`26年国补门店财务统筹表.xlsx`（包含 4 个标准 Sheet）
3. **家电台账**：`家电台账.xlsx`（1 个 Sheet，见第6节）
4. **数码台账**：`数码台账.xlsx`（1 个 Sheet，见第6节）

### 1.1 输入、发布与金额单位

两份工作簿读取清洗阶段发布的 `国补明细/`；两份台账读取原始数据目录，不依赖本次清洗结果。均写入同级 `国补报表/`。路径保护、运行锁、依赖检查和逐文件发布见[项目架构](architecture.md)。

`汇总` Sheet 金额单位为万元，其他工作表金额单位为元，均显示两位小数。

## 3. 源数据契约

8份清洗明细中，报表直接读取下表前7份；收款单仅为清洗依赖。各文件读取第一工作表，第1行为表头，第2行起为明细；按表头名称定位字段，同名图片列按第5.4节分范围定位。

### 3.2 公共字段匹配规则
1. **大类归类口径**：
   - `财务大类 == '数码'` 归为数码；
   - 其余所有财务大类统一归为家电电脑。
2. **状态分类口径**：
   - `已回款`、`审核通过未回款`、`待审核`、`审核失败`、`未上传`。共享读取保留原始状态。上传情况汇总不将审核终止转为审核失败；未匹配回款的审核终止不计上传状态金额和笔数，不列入失败明细。清洗后已为已回款的记录正常计入。财务统筹表保留审核终止原状态；最终匹配表仍优先显示银联备注已退货。源文件不修改。
3. **退货单据排他规则**：
   - `销售用券情况统计.xlsx` 中的 `退货-原单` 与 `退货-退单` 记录，在品类品牌维度聚合时必须严格排除。
4. **门店发生表退货标记**：
   - `银联交易明细门店.xlsx` 的 `备注` 字段取值为 `已退货` 时，最终匹配表将该单据状态直接锁定为 `已退货`。

5. **业务键冲突**：
   - 财务统筹上传索引按参考号取 `更新时间` 最新记录；时间并列时，比较状态及发票号。同键内容一致的重复候选可用，不同内容按未命中处理。
   - 发票索引按发票号码比较开票类型、状态和商品组合；审核失败的商品名称索引按发票号码比较商品名称。同键内容不同则按未命中处理。
   - 上述冲突由 `UniqueIndex` 统一判定并输出冲突键数量及前5个键示例。空键不参与匹配。销售商品与销售单据的候选唯一性分别按第5.1.1节判断。

### 3.3 全局字段类型与格式规范

各 Sheet 字段定义遵循以下统一格式代码与对齐规则，业务表头列无需重复展开格式细节：

| 逻辑类型 | Excel 存储类型 | 格式化代码 (Number Format) | 水平对齐 | 说明 |
|---|---|---|:---:|---|
| **ID / 编码 / 单号 / 文本** | Text | `常规` | 居左 | 强制以纯文本写入，防止科学计数法与前导零丢失 |
| **机构代码 / 状态 / 类型** | Text | `常规` | 居中 | 状态、终端号、地区编码等短标识 |
| **金额（元）** | Number | `#,##0.00;[Red]-#,##0.00` | 居右 | 单位元，保留两位小数，负数红字；空值留空，无法解析的文本（如以逗号作小数点的 `3000,00`）原样保留，不删除逗号、不按 0 填写 |
| **金额（万元）** | Number | `#,##0.00;[Red]-#,##0.00` | 居右 | 单位万元，保留两位小数，负数红字 |
| **数量 / 笔数 / 序号** | Number | `#,##0` | 居右 / 居中 | 正负整数，千分位分隔 |
| **比率 / 占比** | Number | `0.00%` | 居右 | 百分比，保留两位小数 |
| **日期** | Date | `yyyy-mm-dd` | 居中 | 原生 Excel 日期 |
| **日期时间** | DateTime | `yyyy-mm-dd hh:mm:ss` | 居中 | 原生 Excel 日期时间 |

### 3.4 规则 REF-MERCHANT-01：本店商户号解析
- **用途**：清洗阶段已筛选回款商编，报表仍以已上传明细解析出的本店商户号校验并筛选。
- **解析算法**：
  1. 家电电脑本店商户号：动态提取自 `已上传家电电脑.xlsx` 的 `商户号` 字段（遍历全部数据行，校验唯一非空商户号；无有效值或多个不同值时报错）；
  2. 数码本店商户号：动态提取自 `已上传数码.xlsx` 的 `商户号` 字段（遍历全部数据行，校验唯一非空商户号；无有效值或多个不同值时报错）；
  3. 筛选条件：凡涉及门店回款流水筛选，统一执行 `核销商编 == 本店对应品类商户号`。

### 3.5 异常颜色识别规则
- **粉色异常填充**：十六进制色彩 `FFFFC7CE` / `#FFC7CE`（回款明细异常标记）。
- **黄色异常填充**：十六进制色彩 `FFFFEB9C` / `#FFEB9C`（发票明细异常标记）。
- **解析方式**：通过流式解压读取底层 `xl/styles.xml` 与 `xl/worksheets/sheet1.xml`，通过 XF 映射精确匹配单元格背景填充色。

### 4.1 `汇总` Sheet 规格

#### 4.1.1 动态计算公式
1. **发生额与笔数**：取自 `销售用券情况统计.xlsx`，按大类归类口径划分。金额汇总 `补贴额`；笔数汇总 `数量`（净额）。
2. **已回款及上传状态明细**：取自两份已上传明细，按 `状态` 分类：`已回款`、`审核通过未回款`、`待审核`、`审核失败`。金额汇总 `补贴金额`；笔数统计明细记录行数；同一 `实时清分UUID` 的重复记录只保留 `更新时间` 最新的一条（最新时间相同而状态不同时各状态各计一次），去掉的条数输出告警，`实时清分UUID` 为空时不去重；`审核失败明细` 按同一规则去重，与汇总笔数一致。汇总按上传记录（`实时清分UUID`）去重，清洗与财务统筹表按销售（参考号）取最新；审核失败仅统计状态为审核失败的记录，排除审核终止。
3. **关联差额指标**：
   - `未回款金额 = 国补发生额 - 国补回款额`；`未回款笔数 = 国补发生笔数 - 国补回款笔数`
   - `未上传金额 = 未回款金额 - 审核通过未回款金额 - 待审核金额 - 审核失败金额`
   - `未上传笔数 = 未回款笔数 - 审核通过未回款笔数 - 待审核笔数 - 审核失败笔数`
4. **比率分析指标**：
   - `发生额占比 = 对应大类发生额 / 总发生额`
   - `回款率 = 对应大类回款额 / 对应大类发生额`
   - `综合回款率 = (对应大类回款额 + 对应大类审核通过未回款额) / 对应大类发生额`
   - `未回款占比 = 对应大类未回款额 / 对应大类发生额`
   - `分类未回款占比 = 分类未回款金额 / 对应大类未回款总额`

#### 4.1.2 布局结构
- 列宽：A 列 `38.0`；B 至 G 列统一为 `20.0`。
- Row 1: 主标题 `国补上传情况汇总`（A1:G1 合并居中，深蓝底白字，ht=30）

- Row 5-6: 双层分组列头（`项目`、`家电电脑`、`数码`、`合计`；子列 `金额（万元）`、`笔数`，ht=30）

### 4.2 `品类品牌汇总` Sheet 规格

#### 4.2.1 动态聚合规则
- **数据源**：`销售用券情况统计.xlsx`，排除 `备注` 为 `退货-原单` 与 `退货-退单` 的记录。
- **标准品牌排序**：冰箱为博世、海信、海尔、美的、美菱、西门子；彩电为 TCL、创维、华为（终端）、海信、海尔。只输出实际存在的组合，其余标准顺序见 `src/reporting/summary_data.rs` 的 `STD_CATEGORIES`。
- **维度交叉**：按照源数据中实际出现的 `财务大类 + 品牌` 进行二维动态透视，不设固定品牌数量限制；对于基准品类与品牌保持标准业务序列，后续新增品类与品牌自动在末尾动态追加输出。
- **追加顺序与空维度**：新增品类按文本升序追加到标准品类末尾；新增品牌按文本升序追加到所属品类标准品牌末尾。空品类、空品牌也保留，按空字符串参与相同排序；只输出排除退货后实际存在的组合，不补造组合。
- **展开列**：横向展开 5 种状态：`已回款`、`审核通过未回款`、`待审核`、`审核失败`、`未上传`，每种状态各含 `补贴金额（元）` 与 `数量` 2 列。
- **非展示状态**：五种状态以外的备注（含空备注）保留其品类品牌组合，但不计入展示状态的金额和数量。仅有非展示状态记录的组合仍输出一行，五组数值均为短横线。
- **大类合并**：A 列相同财务大类的连续数据行必须在输出时**动态合并单元格**并垂直居中。
- **数值留白**：金额为 0 且数量为 0 的交叉单元格统一显示短横线 `-`。

#### 4.2.2 12 列输出结构与表头布局
- 列宽：A 列 `16.0`，B 列 `20.0`，C 至 L 列（5 种状态展开列）统一为 `16.0`。
- Row 1: 主标题 `品类品牌汇总`（A1:L1 合并居中，深蓝底白字，ht=30）
- Row 2: 副标题说明（A2:L2 合并，ht=22）
- Row 3: 空白分隔行（ht=8）
- Row 4-5: 双层表头（柔和中蓝 `#5B9BD5` 填充，加粗白字居中，ht=30）：
  - A4:A5 合并居中 `财务大类`；B4:B5 合并居中 `品牌`；
  - C4:D4 合并居中 `已回款`（C5: `补贴金额（元）`，D5: `数量`）；
  - E4:F4 合并居中 `审核通过未回款`（E5: `补贴金额（元）`，F5: `数量`）；
  - G4:H4 合并居中 `待审核`（G5: `补贴金额（元）`，H5: `数量`）；
  - I4:J4 合并居中 `审核失败`（I5: `补贴金额（元）`，J5: `数量`）；
  - K4:L4 合并居中 `未上传`（K5: `补贴金额（元）`，L5: `数量`）。

### 4.3 `审核失败明细` Sheet 规格

#### 4.3.1 相对排版布局算法
1. **数据提取**：分别从两份已上传表中提取 `状态 == '审核失败'` 的记录；家电电脑记录以其 `发票号码` 关联 `发票明细.xlsx` 的 `数电发票号码` 补齐 `主要商品名称`。
2. **排序规则**：家电电脑审核失败记录按关联得到的 `商品名称` 升序排列，商品名称为空的记录排在最后；数码区块没有商品名称列，保持源数据顺序。
3. **相对行号生成**：
   - Row 1: 主标题 `审核失败明细`（A1:J1 合并居中，ht=30）
   - Row 2: 副标题说明（A2:J2 合并，ht=22）
   - Row 3: 空白分隔行（ht=8）

### 5.1 Sheet 1: 最终匹配表（全部的国补发生数据上匹配）规格

#### 5.1.1 匹配算法与级联逻辑
1. **底表流水基准**：数据行与 `1.门店国补发生表` 完全一致。每行自增生成正整数 `序号`（1, 2, 3, ...）。
2. **大类/品牌/产品型号：销售用券优先，发票整组兜底**：
   - 以门店银联记录的非空`检索号`精确匹配清洗后的`销售用券情况统计.xlsx`的非空`参考号`，候选商品组合为`财务大类`、`品牌`、完整`商品名称`，分别对应本表的`大类`、`品牌`、`产品型号`。
   - 同一参考号下按三个字段的完整组合去重；重复记录的组合相同视为唯一候选，出现不同组合则视为歧义，不任选记录，也不优先选择原销售或退货记录。
   - 唯一候选且三个字段均非空时整组使用销售商品信息；即使与发票商品信息不同，也以销售为准。销售路径不要求已上传或存在发票号，退货记录同样适用。
   - 未命中销售、候选有歧义或任一字段为空时，三列整组回退到发票路径：以本表的非空`发票号`精确匹配`发票明细.xlsx`的`数电发票号码`，读取`大类`、`品牌`和清洗后的完整`主要商品名称`。
   - 发票号为空或发票未命中时三列留空；发票单个字段为空时，仅对应字段留空。不在销售与发票之间逐列拼接，不通过匹配单据号另行查找销售商品。发票号可按下方规则4通过销售单据兜底取得。
   - 产品型号保留所选来源的完整商品名称，不额外拆分型号，不改写商品名称中的品牌。发票商品字段的生成规则见[清洗规则第3.3节](cleaning-rules.md#33-主要商品名称)。
   - 空值沿用清洗明细的空字符串口径；参考号和商品字段不增加修正、去空格或模糊匹配。上述优先级仅影响三列商品字段，状态、发票号及红冲判断仍按下列规则执行。
3. **状态列多级判定**：
   - **第一优先级（已退货）**：若门店发生表 `备注 == '已退货'`，本表状态直接填入 `已退货`；
   - **第二优先级（上传状态命中）**：非退货单据以 `检索号` 关联 `3.门店上传明细` 的 `检索参考号`，命中则保留其清洗后 `状态`（包括 `已回款`、`审核通过未回款`、`待审核`、`审核失败`、`审核终止`）；
   - **第三优先级（未提交兜底）**：未在上传明细中命中的单据统一填入 `未提交`。
4. **发票号：上传优先，销售单据关联蓝票兜底**：
   - 先以`检索号`关联上传明细的`检索参考号`，取得非空`发票号码`。上传已有非空号码时保持原值，即使发票明细未命中，也不启动兜底；不对上传号码增加蓝票限制。
   - 上传未命中或发票号码为空时，以非空`检索号`精确匹配清洗后销售用券的非空`参考号`，提取全部非空`匹配单据号`并去重；只有一个不同值时继续，未命中或多个不同单据号时发票号留空。销售商品组合是否完整、是否有歧义不影响此独立单据判断。
   - 用唯一销售`匹配单据号`按[清洗规则 §10.10](cleaning-rules.md#1010-数电发票号码匹配)取得蓝票号码，共用 `BlueInvoiceCandidates`；本节仅规定销售单据选择及兜底触发条件。
   - 兜底成功的号码写入本表`发票号`，统一用于规则2的发票商品兜底及规则5的红冲判断；状态仍按规则3判断，未上传记录取得发票号后仍显示`未提交`。空关联键不参与匹配，不猜测或修正单据号。
5. **发票红冲状态校验**：
   - 当本表 `发票号` 非空时，以该发票号在 `发票明细.xlsx` 的 `数电发票号码` 中精确检索：
     - 若命中且 `开票类型 == '红票'` 或 `开票状态 == '已红冲'` $\to$ 填入 `是`；
     - 若命中且状态正常（`开票类型 == '蓝票'` 且 `开票状态 == '开票完成'`） $\to$ 留空；
     - 若未在底库中命中，或命中但不满足红票/已红冲条件，保持留空；
   - 发票号本身为空的记录，`发票是否红冲` 统一保持留空。

## 6. 家电、数码台账

### 6.1 共同规则

| 输出文件 | 工作表 | 源文件（选择规则同清洗回款） | 筛选商户 |
|---|---|---|---|
| `家电台账.xlsx` | `家电台账` | `yyyy年以旧换新补贴明细.xlsx` | `89813015722APT1` |
| `数码台账.xlsx` | `数码台账` | `yyyy年数码补贴明细.xlsx` | `89813014812B06R` |

1. **提取**：排除 `汇总` 工作表；按工作表顺序合并，保持源行顺序；按商户编码精确筛选。保留重复记录与正负金额，不去重、不汇总、不沉底、不填色。不使用清洗后的回款明细。
2. **字段定位**：按表头名称定位，表头首尾空白不计入字段名；同义字段由 `resolve_synonym_column` 定位，同时出现多个候选为结构异常。缺少表头或源单元格为空时留空，不按相邻列或工作表名推断。
3. **批次分组与序号**：筛选后按 `拨付批次`（去除首尾空白，空值作为一个批次）首次出现的顺序分组，不按批次名称排序；同批次记录集中输出，批次内保持源工作表及源行顺序。分组仅集中排列明细，不合计、不去重。分组后全表从 `1-01` 连续递增（`1-99` 后为 `1-100`），跨批次、跨工作表不重置，以文本写入。不读取历史台账：仅当旧批次内容及行顺序不变、新批次只追加在源数据末尾时，原记录的顺序与序号保持不变。
4. **类型**：时间字段写为日期时间（`核销日期` 为日期），无法识别的文本原样保留（如 `创建时间` 的 `7.19-8.4`）；金额写数值、显示两位小数；比例写数值、显示百分比；无法解析的金额或比例保留原文本（如补贴限额文本）；其余字段（单号、商户号、参考号、SN 码等）以文本写入。
5. **版式**：第1行合并 A1:Z1 写标题，第2行为26列表头，第3行起为数据；冻结前两行，筛选范围从表头开始；样式沿用第7节。筛选后无记录时仍输出标题与表头。
6. **发票状态**：第2列；第3列为各台账专用字段（家电 `品牌品类`、数码 `发票头/购买方名称`），其后为 `序号`。读取文件名日期最新的 `发票_yyyymmdd.xlsx`（选择与结构校验同清洗第3节），家电以 `发票号`、数码以 `发票号码` 精确匹配 `数电发票号码`；`开票状态` 为 `已红冲` 时填写 `已红冲`，其他状态、未匹配或发票号码为空时留空。不读取源表同名列。非空 `数电发票号码` 重复时台账失败，不任取一条。
7. **失败**：缺少补贴明细、商户筛选字段或发票文件/列时，对应台账失败并保留旧文件；两份台账独立生成、发布，不因清洗失败跳过。

#### 6.2.3 品牌品类

由 `商品名称` 与 `编码品类` 共同提取：

1. `编码品类` 为空时留空。
2. 品类取 `编码品类` 中 `-` 之后的部分（如 `A03-洗衣机` → `洗衣机`）；不含 `-` 时取整格。
3. 品牌依次取自：去掉发票式 `*品类*` 前缀后的 `商品名称` 首或尾；`编码品类` 品类文本的首或尾（识别后从品类中去掉）；以下完整型号，不按前缀或相似型号推断。只识别下列写法，忽略大小写；同一文本首尾出现多个品牌视为未识别。
   - 品牌写法：海尔、卡萨帝、统帅、Leader、美的、小天鹅、COLMO、华凌、东芝、海信、Vidda、格力、TCL、创维、美菱、奥克斯、A.O.史密斯、西门子、博世、万家乐、方太、小鸭、科龙。
   - 完整型号：`TNDD20-08AIDE` 小天鹅、`65A6Q` 海信、`85A6Q` 海信、`KFR-50GW/CX2S` COLMO、`VL5R-PRO` Vidda。
4. 品牌归并：`A.O.史密斯` → `AO史密斯`，`Leader` → `海尔`，`Vidda` → `海信`，`东芝` → `美的`；其余按清洗第10.11节（卡萨帝、统帅 → 海尔；华凌、小天鹅、COLMO → 美的等）。台账专用归并不影响其他报表。
5. 输出 `品牌` + `品类`，不加分隔符（如 `卡萨帝洗衣机` → `海尔洗衣机`）；无唯一品牌时只填品类。

### 6.3 数码台账

标题：`2026年数码以旧换新活动商家交易数据台账（线下）`

26列：`拨付批次`、`发票状态`、`发票头/购买方名称`、`序号`、`提交时间`、`商户订单号`、`参考号`、`销售企业名称`、`门店名称/县域编码`、`商户编号`、`核销日期`、`商品编码`、`销售金额`、`补贴金额`、`补贴比例/补贴限额`、`SN码`、`原始SN码`、`券号/数据唯一标识`、`所在地区`、`类别`、`商品名称`、`发票号码`、`物流单号`、`备注`、`ID`、`客户购买品类`。

#### 6.3.1 字段映射与缺失字段

只接受以下旧源字段：`销售企业名称`／`销方名称`，`商户编号`／`经销商编号`，`销售金额`／`应收销售金额`，`补贴金额`／`补贴销售金额`，`类别`／`品类`，`商品名称`／`商品明细`，`券号/数据唯一标识`／`券号`。其余字段只读同名字段；发票只用于第6.1节的发票状态及第6.3.2节的购买方名称。

过渡期批次缺少 `提交时间`、`门店名称/县域编码`、`核销日期`、`补贴比例/补贴限额`、`原始SN码`、`券号/数据唯一标识`、`物流单号`、`ID`、`客户购买品类` 时留空；`交易时间` 不用于补充 `提交时间` 或 `核销日期`。

#### 6.3.2 发票头/购买方名称

以 `发票号码` = `数电发票号码` 读取 `购方名称`，不读取源表同名列；发票号码为空、未匹配或购方名称为空时留空。
