# 发票交错单据号提取修复

2026-10-08，基线 `bf37c80`。用户同意修复备注中英文字母、数字交错单据号被截断的问题。范围为完整提取包含数字的连续字母数字串；既有日期、长度、唯一性、排序和填色算法不改。

## 复现与根因

实际样本：最终匹配表第2行、发票明细第13955行，备注含 `销售日期:2026-01-25 单据号:收款ZG2J000424`，清洗后的匹配单据号为空。

通过 `InvoiceJob.run` 读取真实格式的最小XLSX夹具，运行 `cargo test --locked interleaved_document_number_survives_invoice_cleaning -- --nocapture`，两次得到相同失败：实际 `Empty`，预期 `260125ZG2J000424`。

按可能性依次检查提取截断、长度拒绝、日期未提取。临时探针结果：日期提取为2026/01/25，单据号只捕获 `收款ZG2`，完整 `ZG2J000424` 可以通过长度校验。旧正则仅接受前置字母后接数字，遇到数字后的字母即停止，故根因是提取截断。临时 `[DEBUG-invoice-token]` 探针已删除。

## 最小修复与测试

单据主体由 `[A-Za-z]*[0-9]+` 改为 `[A-Za-z]*[0-9][A-Za-z0-9]*`，允许数字后继续出现字母、数字，仍要求至少一个数字。复用现有收款前缀剥离、日期提取、10位/11位/定向9位处理及唯一性规则。

修复后原复现通过。新增任务入口保护测试覆盖交错单据号、单据号/单据收款号标签、收款前缀、日期缺失和冲突、不同单号冲突、同号重复、长度过短/过长以及纯字母拒绝。16个发票测试全部通过。

`cargo test --locked`：165个单元测试、10个集成测试通过，1个旧样本验收按原配置忽略。`cargo check --locked`、`cargo clippy --locked --all-targets -- -D warnings`、`cargo fmt --check`、`git diff --check`及release构建通过。规范及方案两路审查均无发现。
