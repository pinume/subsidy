# subsidy 项目架构

## 模块职责

| 模块 | 职责 |
|---|---|
| `app/` | 路径交互、运行锁、8类清洗调度、本次发布状态和报表依赖检查 |
| `jobs/` | 发票、已上传、银联、回款、收款单、销售用券的清洗与业务匹配 |
| `jobs/context.rs` | 单次清洗的表、查询索引与匹配统计上下文，集中管理生命周期与索引访问 |
| `model/`、`utils/` | 清洗结果的类型、十进制金额、日期、文本和单据号处理 |
| `io/` | 原始 Excel 读取、明细写出、路径保护及结果发布 |
| `reporting/data.rs`、`reader.rs` | 标准明细读取、表头映射、字段类型与列选择、状态归并、本店商户号及异常底色解析 |
| `reporting/summary_data.rs` | 汇总指标、品类品牌汇总、发票商品索引和异常记录行索引 |
| `reporting/summary_wb.rs` | 计算和筛选汇总数据，渲染汇总 Excel |
| `reporting/finance_wb.rs` | 最终匹配、门店发生、累计回款和上传明细工作表 |
| `reporting/excel.rs`、`styles.rs` | 报表的日期与金额写入及统一样式；`ReportError` 统一承接 xlsx 写出错误与文本错误，公开接口仍返回 `String` |

## 数据流

```text
用户输入原始目录
  → 校验源目录与两处输出目录的真实路径
  → 取得 国补明细/.combine.lock 的标准库文件锁
  → 按顺序处理并发布8类明细，记录每类本次发布状态
  → 检查各报表的依赖
  → 首份符合依赖的报表加载6份共同明细
  → 上传汇总按需解析底色，计算共享指标和异常记录索引
      → 汇总 Excel
  → 财务统筹复用共同明细，额外读取门店银联明细
      → 财务统筹 Excel
  → 逐文件发布、报告结果、释放内存与文件锁
```

清洗后的 Excel 继续作为清洗与报表的边界，异常颜色和日期类型从文件读取。原始 Excel 的读取器与报表读取器分别服务不同的数据契约，不强行合并。

金额在这条边界上经过一次往返：清洗层的 `Decimal` 由 `write_table()` 转为 `f64`，写入 XLSX 数值单元格；报表读取层再由 `cell_to_decimal()` 把 `Data::Float` 转回 `Decimal`。写出时不做舍入，`0.00` 只是显示格式。转回时统一使用 `Decimal::from_f64`，与清洗层一致，不使用 `from_f64_retain`：后者保留二进制浮点尾差，会使理论为零的累计值通不过 `is_zero()`，使零分母比例（见[报表规则第 4.1 节](reporting-rules.md)）和汇总格的 `-` 显示失效。`clippy.toml` 禁用了 `from_f64_retain`。`from_f64` 按约 15 位有效数字规整，更高精度的数值会被舍弃；`src/reporting/float_roundtrip_tests.rs` 经真实 XLSX 往返覆盖该契约。

`io/paths.rs` 集中定义 `国补明细/` 和 `国补报表/`，用于路径保护、目录创建和报表调度。旧英文输出目录不迁移、不读取。原始工作簿按工作表原顺序调用 `worksheet_range()`，任一读取错误包含文件路径、工作表名和原因；对应类别不发布，其余类别继续。

## 收款单退货识别

收款单退货规则见[清洗业务规则第9.5节](cleaning-rules.md#95-备注生成与关联匹配)：先仅将源字段 `销售类别 = 退货` 的记录标为 `退货-退单`，其他备注全部留空。随后仅从实际退单出发，用非空 `原票号` 精确匹配 `匹配单据号`；命中正常销售单时标为 `退货-原单` 并结束该分支，命中零售补差或同型号换货单时保持空备注，继续沿其原票号追溯。

支持多级补差／换货链和同号多行，保持记录数量与源顺序。空键、未匹配、其他销售类别或已访问记录终止对应分支；不猜测原单、不强制金额归零、不新增追溯异常报表。仅补差／换货而没有实际退货的原单不生成退货备注，也不再生成补差／换货专用备注。

销售用券继续只使用收款单的非空备注。空备注按既有规则进入上传状态匹配，未命中时填为 `未上传`，不会强制保留为空。

## 共享与隔离

任务执行通过 `PipelineContext` (`jobs/context.rs`) 管理显式执行上下文与中间数据，彻底消除 thread-local 隐式通道。销售用券构建两份上传数据的状态索引时，通过 `Job::run_shared()` 取得清洗表：已上传与回款任务经 `PipelineContext::cached_table()` 共享已缓存的同一张表，未缓存时在上下文中运行原任务并缓存。两条路径共用索引累积逻辑，保留参考号、发票号码下全部候选及原有歧义判定。

报表调度使用局部 `OnceCell<Result<CommonInputs, String>>`。共同明细、表头和商户号只加载一次，通过借用复用，不复制整表；完整成功流程共解析7份报表输入。共享数据只存在于一次报表阶段，不跨目录或运行复用。

共同输入加载失败时，两份报表都报告该错误。异常底色读取、汇总计算、输出生成及发布失败只影响当前报表，另一份继续按自己的依赖处理。未成功发布的清洗类别不能通过旧文件绕过。

审核失败、粉色本店异常回款和黄色且非粉色异常发票的选择结果以源行索引保存。汇总 Excel 使用这些选择结果，并保留排序和分组规则。财务统筹由领域服务 `TransactionReconciler` (`reporting/reconciler.rs`) 借用已加载的销售、上传与发票明细构建查询索引。商品信息优先按银联检索号匹配销售用券参考号，使用唯一且完整的财务大类、品牌、完整商品名称组合；相同组合的重复候选可用，不同组合保持歧义。未命中、歧义或任一字段为空时，三列整组回退到上传发票号关联的发票大类、品牌、完整主要商品名称。完整商品名称写入产品型号列，销售与发票字段不混合。发票号优先使用上传记录的非空号码，仅为空时按销售参考号取得唯一非空匹配单据号，再查找关联蓝票（与清洗第10.10节共用 `invoice::BlueInvoiceCandidates`）：已完成蓝票号码唯一时优先使用，多个已完成号码留空；无已完成蓝票时仅接受唯一蓝票号码。单据索引与销售商品组合索引独立，空键和歧义不任选。已上传明细先按参考号只取 `更新时间` 最新的记录（与清洗第10.12.2节、汇总表 UUID 去重共用 `utils::latest::latest_by_key`）。已上传明细、发票明细及发票商品名称索引通过 `UniqueIndex` 处理业务键：相同业务键的多条记录若内容一致（如重复导出）正常保留，若内容不同则标记为冲突并按未命中处理（不猜测、留空），同时向用户输出包含冲突键数量与前5个键示例的注意告警。最终发票号统一用于商品发票兜底及红冲判断，状态仍按门店备注和上传记录判断。

报表列在 `data.rs` 绑定源字段与日期、日期时间、金额、比例或文本类型，由 `excel.rs` 统一写入。门店发生表与回款表按实际表头选择类型，重排列不改变字段含义。审核失败明细的发票金额保留原有空值转零口径，回款表的其他支付保留文本呈现；其他金额字段保留空值。上传明细的重复图片列、同义字段和品类专有空列仍按其外部数据契约解析。

品类品牌汇总由 `summary_data.rs` 内部的 `CategoryBrandSummary` 集中负责退货排除、金额数量聚合、标准与新增品类品牌排序、五状态投影和缺省补零。调用者取得有序品类分组及固定五状态结果，不接触聚合索引。`summary_wb.rs` 仅负责 Excel 格式、同时为零时显示短横线和同品类合并；计算与实际工作簿分别通过各自 interface 验证。

## 接口与验证

库继续导出 `generate_summary_workbook`、`generate_store_finance_workbook`。独立工作簿调用自行加载共同输入，CLI 使用内部的共享输入入口。内部报表类型不作为新增公开接口。

普通测试覆盖业务规则、路径保护、锁、7份输入单次解析、颜色和商户筛选及发布失败保留旧结果。`tests/full_pipeline.rs` 使用小型原始 Excel 夹具，经真实 CLI 校验8类清洗、两份 Excel 报表、匹配结果与源文件未变。真实数据验收经统一 CLI 核对8份明细、两份工作簿，并比较独立工作簿接口的输出内容。业务规范见 [清洗规则](cleaning-rules.md) 与 [报表规则](reporting-rules.md)；运行命令见下节。

## 运行与验证

`cargo run --locked` 后按提示输入源目录，支持绝对路径、相对路径和成对引号包裹的路径；无效输入重新提示，EOF 正常退出。全部成功（包括有业务键冲突告警但已发布）或 EOF 的退出码为`0`；清洗失败、报表失败、跳过报表或无法开始处理为`1`。

原始文件只读。输出真实路径与源目录或另一输出目录重叠时拒绝处理。成功结果覆盖同名文件，失败保留对应旧文件；旧`cleaned/`和`subsidy_summary/`不迁移、不读取。完整流程通过`国补明细/.combine.lock`的标准库文件锁防止并发；锁文件保留，进程结束后由操作系统释放。

报表所需类别本次未成功发布时，列出原因并跳过，不读取旧明细。两份 XLSX 分别生成和发布；单份失败保留该旧文件，不阻断另一份报表。

真实数据核对与验收测试见 [真实数据核对](agents/real-data.md)。
