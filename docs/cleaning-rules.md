# subsidy 清洗业务规则

本文描述当前项目的8类原始 Excel 清洗规则。本轮调整规格见[清洗规则调整规格](cleaning-review-spec.md)。旧样本数量仅作历史记录，当前数据须重新核对。统一运行方式见 [README](../README.md)，整体数据流见[项目架构](architecture.md)。

## 1. 项目范围与安全约束

- 本项目用于处理用户在终端交互界面中指定的源文件夹中的数据，本文将该文件夹记为`输入目录`。
- 仅处理`输入目录`直接包含的`.xlsx`文件，排除以`~$`开头的Excel临时文件；各类别的文件名筛选规则见对应章节。
- 正式处理结果仅在用户通过终端界面指定源目录并执行处理时生成；验证方法见 [运行与验证](architecture.md#运行与验证)。
- 处理程序使用Rust开发；`.xlsx`源文件使用`calamine`读取，`.xlsx`结果使用`rust_xlsxwriter`写入；日期与时间使用`chrono`处理，金额与比例使用`rust_decimal`按十进制处理，不使用二进制浮点数参与金额判断。终端交互界面使用Rust标准库`std::io`实现（`println!`输出、`stdin().read_line()`输入），不引入界面依赖。
- `输入目录`及其中所有文件均为只读数据源，不得修改、覆盖、移动、重命名或删除。
- 所有处理结果必须直接写入所选`输入目录`的父目录下的`输出目录`，不得写入`输入目录`。
- 清洗阶段的8份输出数据文件均采用单表结构：每个Excel文件只包含一个工作表，不得增加汇总表、说明表或其他附加表。
- Excel输出工作表的标签名称不作指定，使用`rust_xlsxwriter`创建工作表时的默认名称，不得为此额外重命名。
- 源数据中的空值默认保持为空，不得写成`0`、`null`、`None`或其他占位内容。
- 除文档明确规定的转换外，不得自行清洗、修正、筛选或推断数据。
- 上述约束适用于全部数据组；各节只列补充或例外。

### 1.1 输入与输出路径

- 文中的`输入目录`是用户所选源文件夹的路径占位符，并非要求文件夹实际名为`输入目录`。处理程序须在终端交互界面提供源文件夹路径输入；绝对路径直接使用，相对路径以程序启动时的当前工作目录为基准（开发阶段在项目根目录执行`cargo run`时即为项目根目录），开始处理前解析为绝对路径并确认该路径存在、是文件夹且可读取。源文件夹可位于项目根目录内或外，不受程序所在目录限制。
- 路径输入时须去除首尾空白；如用户从文件管理器拖入路径导致首尾带有成对的单引号或双引号，应先去除该对引号再解析。
- 开发样本可存放于项目根目录下的`data/`；本次2026-10-01验收使用外部样本目录的副本，仅用于核对现有数据，正式处理时不得默认固定读取此路径。
- 本文将所选`输入目录`的父目录下的`国补明细`文件夹记为`输出目录`；该文件夹与`输入目录`同级，不存在时须自动创建。输出路径随用户所选源文件夹确定，与项目根目录、程序所在目录及当前工作目录无关。
- 所有数据组的结果文件直接写入`输出目录`，不另建年份子目录。
- 例如用户选择`/某路径/源数据/`时，发票结果写入`/某路径/国补明细/发票明细.xlsx`；选择当前样本`data/`时，结果写入项目根目录下的`国补明细/`。
- 每次处理只针对同一个年份的数据；各类别中的年度源文件不得跨年度合并。
- 每个数据组使用固定输出基名及`.xlsx`扩展名。下表中的输入模式用于标明读取路径，文件名有效性和具体选择规则仍按各处理章节执行；`yyyy`、`yyyymmdd`及时间戳均为文件名中的对应数字：

### 1.2 终端交互界面

- 处理程序提供简单的终端文字界面：使用标准库`println!`显示提示，使用`std::io::stdin().read_line()`接收源文件夹路径；界面不引入第三方依赖，数据处理依赖不受此限制。
- 终端输出与输入均使用UTF-8；Windows环境下须确保中文提示正常显示，不得因控制台编码导致路径或提示乱码。
- 每次运行先提示用户输入源文件夹路径。路径为空、不存在、不是文件夹或不可读取时，显示具体原因并重新提示，不得开始处理。
- 路径有效后立即依次执行下列全部8类数据，不再显示类别菜单或接收类别编号：

| 执行顺序 | 数据类别 | 对应处理章节 |
|---:|---|---|
| 1 | 发票明细 | 第3节 |
| 2 | 数码已上传数据 | 第5节 |
| 3 | 家电、电脑已上传数据 | 第5节 |
| 4 | 门店银联交易明细 | 第6节 |
| 5 | 家电电脑回款明细 | 第7节 |
| 6 | 数码回款明细 | 第8节 |
| 7 | 收款单统计 | 第9节 |
| 8 | 销售用券情况统计 | 第10节 |

- 部分类别还须从同一`输入目录`只读地引用其他类别的数据源用于校验或匹配；读取引用数据本身不发布结果文件，各类别的输出由调度器分别发布：
  - 数码已上传数据及家电、电脑已上传数据须按第5.7节匹配对应的回款明细（数码↔第8节回款明细数码，家电、电脑↔第7节回款明细家电电脑）。
  - 销售用券情况统计须依次读取第10.6.1节的门店银联交易明细、第10.10节的发票明细、第10.12.1节的收款单统计及第10.12.2节的已上传家电电脑和已上传数码；已上传数据各自引用对应回款明细。
- 某一类别处理失败（包括源文件缺失）不得中断其余类别，须继续处理后续类别，并分别报告各自的成功或失败结果。单个类别内部发生的程序级错误（包括panic）须被捕获并报告为该类别失败，不得导致整个程序退出。
- 处理成功后显示类别及输出文件的完整路径；失败时显示具体错误，不将失败结果作为正式输出。8类清洗结束后，报表调度器按本次成功发布状态检查依赖并生成报表；全部处理完成后程序自动退出。退出码和报表失败行为见[项目架构](architecture.md#运行与验证)。
- 输入源文件夹路径阶段，用户通过`Ctrl+C`或输入结束（Linux/macOS为`Ctrl+D`，Windows为`Ctrl+Z`后回车）终止输入时程序退出；`read_line()`返回0时视为输入结束并正常退出。

### 1.3 开发环境与结果发布

- 项目名称、Cargo包名及Rust库名均为`subsidy`。GitHub仓库名及本地项目路径不因项目名称调整而改变。
- 项目目录与模块职责见[清洗模块架构](cleaning-architecture.md)；本文各数据组的处理和验收规则为实现依据。
- 开发基准为Rust 1.99.0，Edition 2024。项目根目录的`rust-toolchain.toml`固定该工具链版本；`Cargo.toml`声明直接依赖，`Cargo.lock`锁定完整依赖并纳入版本控制。开发、测试、构建与验收须使用同一锁文件。
- 当前直接依赖及固定版本如下，以`Cargo.toml`和`Cargo.lock`为准：

| 依赖 | 版本 | 用途 |
|---|---|---|
| `calamine` | 0.36.1 | 读取`.xlsx`源文件（启用`dates`特性） |
| `rust_xlsxwriter` | 0.99.1 | 写入`.xlsx`结果（启用`chrono`、`rust_decimal`特性） |
| `chrono` | 0.4.45 | 日期、日期时间、时间解析与格式化 |
| `rust_decimal` | 1.43.0 | 金额与比例的十进制运算 |
| `regex` | 1.13.1 | 文件名与备注、摘要文本匹配 |
| `thiserror` | 2.0.20 | 统一错误类型定义 |
| `quick-xml` | 0.41.0 | 报表读取 Excel 样式 XML |
| `zip` | 8.6.0 | 报表读取 XLSX 内部文件（启用`deflate`） |

- 首次准备环境时，安装`rustup`后在项目根目录执行任意`cargo`命令，`rustup`会按`rust-toolchain.toml`自动安装指定工具链。常用命令均在项目根目录执行：
  - 开发运行：`cargo run --locked`
  - 运行测试：`cargo test --locked`
  - 代码检查：`cargo clippy --locked --all-targets`与`cargo fmt --check`
  - 发布构建：`cargo build --release --locked`
- 程序入口为`src/main.rs`；发布构建产物为`target/release/subsidy`（Windows为`subsidy.exe`），可单独复制到其他电脑运行，无需安装Rust或其他运行环境。`target/`目录不纳入版本控制。
- 读取源表时必须按Excel绝对行号、列号定位单元格。`calamine`返回的数据区域从第一个非空单元格开始，读取模块须使用区域起始偏移（`Range::start()`）换算回绝对位置，确保开头空白行、列不会导致本文指定的表头行号和列位置发生偏移；“最后一个实际有值行”须按实际非空单元格计算，不得依赖区域边界或格式化范围。按本文规定生成XLSX格式与填色，不依赖复制源工作簿样式。
- 源单元格可能为文本、数值、布尔、Excel日期序列值或错误值；读取模块须保留原始单元格类型供处理模块判断。遇到Excel错误值（如`#N/A`、`#REF!`）且该单元格属于必需输出字段时，按数据异常终止该类别处理并报告位置。
- 每个类别独立发布其规定的一份XLSX结果。目标文件已存在时，处理成功后直接覆盖，无需再次询问；失败类别保留已有结果。旧`source_data/`目录和历史银联国补结果不迁移、不删除。
- 先在`输出目录`准备本次XLSX临时文件，完成该类别的全部校验，并确认临时文件已成功生成，再替换正式目标文件。替换前保留已有结果；生成、校验或替换任一步骤失败时，恢复或保留原有结果，清理本次临时文件。
- 正式目标文件被其他程序（如Excel）占用而无法替换时，按发布失败处理，恢复原有结果并提示用户关闭占用文件后重试。

### 3.4 匹配单据号

`匹配单据号`的格式为`yymmdd单据号`，日期与单据号直接拼接，不加空格或分隔符。

按以下顺序处理：

1. 解析备注：兼容半角冒号、全角冒号、顿号、空格、换行及无分隔符的写法。解析过程不得改变输出的`备注信息`原文。
2. 提取日期：
   - `销售日期`和`购机日期`视为同一字段，仅提取明确带有这两个标签之一的日期。
   - 同一日期重复出现时按一个日期处理；出现多个不同日期时不作选择，`匹配单据号`留空。
   - 备注中同时出现开具购物发票日期时，不使用该开票日期。
3. 标准化日期：
   - 月份和日期可为一位或两位，一位时自动补零，例如`2026-8-9` → `260809`。
   - 两位年份的点分日期按2000年代处理，例如`26.02.16` → `260216`。
   - 兼容连接符与中文年月日混用，例如`2026-2月21日` → `260221`。
   - 执行已确认的定向修正：`2026-0101` → `2026-01-01`；`202601-04` → `2026-01-04`；`2026-26-29` → `2026-06-29`。
4. 提取单据号：
   - `单据号`和`单据收款号`视为同一字段。
   - 删除开头的`收款`二字；没有该前缀时直接使用原值。
   - 单据号与前后文字紧邻时，不得把后续说明文字计入单据号。
   - 同一个单据号重复出现时按一个处理；出现多个不同单据号时不作选择，`匹配单据号`留空。
5. 标准化并校验单据号：

   | 原始情况 | 处理规则 |
   |---|---|
   | 10位 | 直接使用 |
   | 11位 | 从连续补零段中删除一个多余的`0`，纠正为10位 |
   | 9位且为`ZFP300008` | 在补零段增加一个`0`，纠正为`ZFP3000008` |
   | 其他9位或其他无法得到10位的内容 | 判定无效 |

   11位纠正示例：`ZHLT0000524` → `ZHLT000524`；`ZFTY0000027` → `ZFTY000027`。

- 出现多个不同日期；
- 出现多个不同单据号；

### 10.4 补贴额与数量

- 输出字段`补贴额`直接取源字段`合计`的明细值，不使用最后一行合计数据，也不得自行改用`2026家电国补（计入收入）`或`2026数码国补（计入收入）`。
- 输出字段`数量`根据同一条记录的`补贴额`数值生成：
  - `补贴额 > 0`时，`数量`为`1`；
  - `补贴额 = 0`时，`数量`为`0`；
  - `补贴额 < 0`时，`数量`为`-1`。
- `补贴额`为空或无法解析为数值时，不得按`0`生成数量，应记录为数据异常，待确认后处理。
- 当前源字段`合计`的部分数值带有Excel浮点计算尾差，例如`299.85000000000002`。按第10.7节统一到两位小数后再确定输出金额；判定阈值以第10.7节为准，不得另行设定。当前实测尾差远小于该阈值，未出现影响正负号或`数量`的情况；源数据变化后须重新确认，不得默认尾差一定不影响`数量`。以后若出现无法解释为两位小数金额的源值，不得静默舍入，应报告异常并待确认。

### 10.5 匹配单据号

`匹配单据号`由源字段`单据日期`和`单据号`组合生成，格式为`yymmdd单据号`，日期与单据号直接拼接，不添加空格或其他分隔符。

生成规则：

1. 将源字段`单据日期`解析为日期，并转换为六位`yymmdd`格式；例如`2026-08-29`转换为`260829`。
2. 将源字段`单据号`按文本读取；如果值以`收款`二字开头，仅删除开头的`收款`，其余内容保持不变。没有该前缀时直接使用原值。
3. 将六位日期与处理后的单据号直接拼接。例如，`单据日期=2026-08-29`、`单据号=收款0023000002`时，生成`2608290023000002`。
4. `匹配单据号`必须按文本保存，不得转换为数值、科学计数法或丢失前导零。
5. `单据日期`或`单据号`为空时，`匹配单据号`留空，不得从`收款日期`或其他字段推断；非空日期无法识别时按第10.7节记录异常并停止生成正式输出。

生成`匹配单据号`只新增字段值，不得修改输出中的原`单据日期`或`单据号`。

### 10.6 参考号提取

`参考号`从同一条记录的源字段`明细摘要`中提取，最终非空值必须为`[0-9]{11}N`，即11位数字加大写`N`，例如`16867252734N`。

#### 10.6.1 权威校验集

- 仅使用第6.1节规定的两组门店银联交易明细工作簿中全部有效交易行的源字段`检索号`。完整识别当前及后续新增文件，排除首行汇总、表头及末行提示；重复`检索号`按一个值看待。
- 只有符合`[0-9]{11}N`的`检索号`可进入校验集，不符合该格式的值一律不纳入，也不得使用第5节的`检索参考号`或第7、8节的`交易参考号`替代。
- 当前核对基准：18个门店银联工作簿共13,971条有效交易，`检索号`均非空；不同值13,630个，其中13,614个符合本节格式，其余16个以`W`结尾因而落选。源数据变化后重新计算，不得硬编码这些数量。
- 权威文件缺失、源结构异常或无法完整读取时，必须停止生成正式输出并报告异常，不得绕过校验。

#### 10.6.2 提取与修正顺序

按以下优先级处理每条`明细摘要`，进入较高优先级并得到有效值后，不再用较低优先级候选覆盖：

1. **原样提取**：在摘要全文中查找完整的`[0-9]{11}N`片段。片段前后可为汉字、空格或标点，但不得从更长的数字串或连续字母数字串中截取。仅保留与权威校验集完全相同的值；格式正确但未命中的值仍不得输出。
2. **11位数字补 N**：若无已校验的原样值，读取完整连续的11位数字，补上大写 `N` 后与权威校验集精确匹配。允许纠正已有非标准字母尾缀（当前包括 `W`、`M`、`n`、`nN`、`H`、`B`），数字不得改变。不生成10–12位候选，不跨片段拼接数字，不插入、删除或替换数字。银联只有真实 `W` 而无同数字 `N` 时不得输出 `N`。

每条用券明细按业务只有一个参考号。

每个优先级内先对命中的权威值去重：恰好一个不同值时输出该值；两个及以上不同值时`参考号`留空并记录歧义，不得任选；没有命中时进入下一优先级。`明细摘要`为空或只有`预售`、`倒票`等非编号内容时留空，不得从其他字段推断。提取与修正只改变新增输出字段`参考号`，不得改写源字段`明细摘要`；同一参考号出现在多条明细中不得因此去重、合并或删除记录。

#### 10.6.3 保存与核对

- `参考号`按文本保存，保留11位数字、前导零和末尾大写`N`，不得转换为数值、科学计数法或截断。
- `单据日期`与银联`交易时间`、`补贴额`与银联`优惠金额`仅作复核，不作为参考号校验硬性条件。参考号数量按当前规则重新核对。

### 10.12 备注匹配、沉底与填色

`备注`分三个阶段生成：第一阶段与收款单统计匹配；仍未命中时，第二阶段改用参考号、数电发票号码与已上传数据匹配；两个阶段均未命中时，第三阶段固定填`未上传`。三个阶段均只新增输出字段`备注`的值，不修改任何源数据或其他输出字段，也不改变明细数量。

#### 10.12.1 第一阶段：收款单统计匹配

- 输出字段`备注`按输出字段`匹配单据号`（第10.5节）与收款单统计（第9节）的输出字段`匹配单据号`进行精确文本匹配，两者完全相同才视为命中；只使用已生成的`匹配单据号`，不得改用`单据号`、`单据日期`或其他字段直接对照收款单统计。
- 参与匹配前须先按第9.4和9.5节规则从收款单统计生成`匹配单据号`及`备注`；收款单统计工作簿缺失或结构不符合第9.1节要求时，必须停止生成正式输出并报告异常，不得绕过校验，也不得因此跳过`备注`而继续输出其余字段（与第10.6.1节门店银联权威源、第10.10节发票明细同一严格程度）。
- 一条销售用券明细的`匹配单据号`为空时，本阶段不命中，进入第10.12.2节。
- 一条销售用券明细的`匹配单据号`非空时，在收款单统计中查找相同的非空`匹配单据号`，先剔除空`备注`（空值不参与去重判定），再对剩余的非空`备注`去重：
  - 恰好一个不同值时，输出该值，本阶段命中，不再进入第10.12.2节；
  - 两个及以上不同值时，判定为歧义，本阶段不命中，仍进入第10.12.2节尝试匹配；
  - 未找到相同`匹配单据号`，或找到但对应`备注`均为空时，本阶段不命中，进入第10.12.2节。
- 收款单统计中`匹配单据号`重复（同一单据的多条商品明细，见第9.5.5节）不影响销售用券情况统计的明细数量，也不得据此对收款单统计去重、合并或修改。

#### 10.12.2 第二阶段：已上传数据兜底匹配

- 仅对收款单备注阶段未命中的记录执行。归并后的财务大类为 `数码`（含源 `新业务类`）时只查数码已上传，其他只查家电电脑。两种键均限定同一类别，不跨组。
- 参考号是唯一业务键。非空时与该组 `检索参考号` 精确匹配，采用其非空状态。
- 只有参考号未命中或对应状态为空时，才用 `数电发票号码` 匹配该组 `发票号码`。剔除空状态后，恰好一个不同状态则命中；无状态或多个不同状态则本阶段未命中。
- 仍要求两组已上传及各自回款数据完整可读；依赖缺失或结构异常时本类失败，不跳过字段继续输出。

#### 10.12.3 第三阶段：未命中固定标记

- 第一、第二阶段均未命中时（含空键、查无匹配、任一阶段歧义），`备注`固定填写`未上传`，不再保持为空、不得使用其他占位文字。

#### 10.12.4 沉底与填色

- 第一阶段实际命中的记录沉底并整行填充粉色`#FFC7CE`；第二阶段实际命中及未命中记录在前、不填色。两组各自保持源相对顺序。
- 当前16,618条明细中第一阶段3,355条命中并沉底填粉色；第二阶段兜底11,884条与未命中1,379条保持在前且不填色；源数据变化后重新计算，不得硬编码这些数量。
