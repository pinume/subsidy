# subsidy

将原始 Excel 清洗和国补报表生成整合为一个独立 Rust 程序。

```bash
cargo run --locked
```

输入一次原始数据文件夹路径，程序依次执行8类清洗，再生成两份 Excel 报表及 Markdown 分析报告，完成后退出。支持绝对路径、相对路径和成对引号包裹的路径；输入无效时重新提示，输入结束（EOF）正常退出。

## 输出

输出位于所选原始数据目录的父目录，与原始目录同级：

```text
父目录/
├── 原始数据/                  # 只读
├── 国补明细/                   # 8份标准明细
└── 国补报表/
    ├── 国补上传情况汇总.xlsx   # 5个工作表
    ├── 国补上传情况汇总.md
    └── 26年国补门店财务统筹表.xlsx  # 4个工作表
```

某类清洗失败后继续其余类别。报表只使用本次成功发布的明细；所需类别失败时列出原因并跳过，即使存在旧明细也不使用。上传汇总需要发票、销售用券、两份上传及两份回款；财务统筹额外需要门店银联明细。收款单影响销售用券的清洗，但不直接作为报表输入。

原始文件不修改。输出真实路径与源目录或另一输出目录重叠时拒绝处理。成功的结果覆盖同名文件，失败时保留对应旧文件。XLSX 与 Markdown 完整生成后逐文件发布，未提供跨文件事务；若发布部分失败，会列出已发布文件并将报表记为失败。

旧 `cleaned/`、`subsidy_summary/` 目录及文件保持原样，不自动迁移或读取。原始工作簿逐张读取工作表；任一工作表读取失败时，报告文件路径、工作表名和原因，该类别不发布结果，其余类别继续。

同一 `国补明细/` 的完整流程通过标准库文件锁防止并发运行。`.combine.lock` 是保留的隐藏锁文件，操作系统在进程结束时自动释放锁，无需手动删除。

退出码：全部成功或输入结束为 `0`，清洗失败、报表失败、跳过报表或无法开始处理为 `1`。

## 构建与验证

固定 Rust 1.99.0、Edition 2024。所有代码和依赖配置在本项目内，不需要旁边的 `clean` 或 `subsidy` 工程。

```bash
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets
cargo build --release --locked
./target/release/subsidy
```

完整样本验收使用2026-10-01原始数据，测试会复制到临时目录，通过统一 CLI 运行，核对明细数量、报表指标、Markdown 内容和源文件未变：

```bash
COMBINE_SOURCE_DIR=/path/to/raw-data cargo test --release --locked --test acceptance_test -- --ignored --nocapture
```

样本验收默认标为 `ignored`，普通测试无需本地业务数据。数量基准仅用于验收，不作为运行时限制。
